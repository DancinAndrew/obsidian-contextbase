# 工作假設（M1–M3）

2026-11-12。這份文件列出實作 M1–M3 時，作者的 agent 自己做的假設：plan.md 沒有規定、需要先選一個做法才能往下做的地方。D1–D11 是作者已經做的決定，不在這裡。

每一點都寫了為什麼這樣選，以及如果不對要怎麼改。標「**暫定，待作者拍板**」的是需要作者最後決定的；其餘是一般的實作選擇，作者看過沒意見就照這樣。大多數只要改一個常數或一個函式。

| M4b | 同一個設定檔可以列禁用詞（`saveDeny`）：提到這些詞的記憶不寫入；`about` 指向被排除資料夾的記憶也不寫入 | 延續真實工作測試裡擋敏感資料夾名稱的做法 | 拿掉這個欄位 |

| M6 | 排名權重（D8 的方向，數值是起點，用測試確認順序）：使用者的決定 ×1.3、agent 的決定 ×1.15、事實 ×1.1、進度與一般筆記 ×1.0；記憶的新近度 = 0.5 + 0.5 × 0.5^(天數 ÷ 30)；被取代 ×0.3；範圍加權 α = 0.5；筆記名稱的 BM25 權重是內文的 2 倍 | D8 | 都是常數 |

| M11 | Node 版本下限寫 22.13：記憶中 `node:sqlite` 從這版起不需旗標，沒有實際驗證。FTS5 只在 26.5.0 實測過，所以加 CI 在 Node 22、24、26 測（推上 GitHub 才會跑），而且啟動時先檢查 FTS5，沒有就清楚報錯 | 本機只有 Node 26 | 調 `engines` |

## M2 工具與 hooks

| # | 假設 | 為什麼 | 如果不對 |
| --- | --- | --- | --- |
| H1 | 三個 hooks 由同一支程式處理：`contextbase hook <事件> --client <claude 或 codex>`，讀 stdin 的 JSON | 一處維護兩個 client | — |
| H2 | 開工注入：先用途說明（D11），再接近況，近況上限約 1,500 字元。在 vault 根目錄依主題分組，最多 4 個主題、每個 3 則；在子資料夾或 vault 外時，同範圍的排前面。標籤用英文（decision、progress、next），記憶內容照原文 | Codex 每則 hook 輸出預設上限約 2,500 tokens；標籤給模型看，英文對任何語言的使用者都通用 | 改中文標籤只要改一處 |
| H3 | 第一句話注入：只搜記憶、只附沒被取代的；分數至少是最高分的一半而且超過下限，最多 2 則；每個 session 只做一次 | D7；避免每句話都花 token | 門檻值 |

| H7 | `agent` 對照：`claude-code`→`claude-code`、`codex-mcp-client`→`codex`，其他照原樣記 | M0 實測 | — |
| H8 | `init` 預設只印出要改的地方，不寫入；在終端機回答 y，或加 `--yes` 才寫。範圍分 `--scope vault`（只影響從 vault 開的 session）與 `--scope user`（所有專案）。**預設值暫定 vault，待作者拍板** | 作者問過會不會影響所有專案；正式預設等真實工作測試的結果 | 一個參數 |
| H9 | Claude Code 用官方的 `claude mcp add` 註冊；hooks 寫進 vault 的 `.claude/settings.local.json` 或 `~/.claude/settings.json`，保留原有內容 | 官方指令會處理設定檔的格式 | — |

## 實作中另外做的假設（2026-11-12，請過目）

上表之外，寫程式時還做了下面這些選擇。都是一個常數或一個小函式，作者沒意見就照這樣；要改哪一點，說一聲即可。

這一節和上表的 H3（下限的數值）、H15，是先寫進程式、之後才列給作者看的，沒有做到「先讓作者看過」。

| # | 假設 | 為什麼 | 如果不對 |
| --- | --- | --- | --- |
| I1 | 記憶的索引文字包含它 `about` 連到的筆記名稱，所以搜尋一個主題時，也會找到連到它的記憶 | 記憶常常很短，只靠內文容易漏 | 從索引文字拿掉 |
| I2 | 同名筆記的連結，先對到路徑最短的那篇，一樣長再照字母順序 | 和 Obsidian 的做法一致 | 改成同名時要求寫路徑 |
| I3 | `fetch` 沒指定行號時最多回傳 400 行，並告訴 agent 總共幾行 | 避免一次塞滿 agent 的上下文 | 一個常數 |
| I4 | `fetch` 用實際路徑檢查，vault 裡指向外面的捷徑檔一律拒讀 | 安全：路徑字面上在 vault 裡，不代表檔案在 vault 裡 | — |
| I5 | session 狀態檔保留 30 天，新 session 開始時刪掉更舊的 | 避免 `.contextbase/sessions/` 無限長大 | 一個常數 |
| I6 | `init` 寫入的 hooks 逾時都設 15 秒 | 大型 vault 第一次建索引要幾秒；Claude Code 對送出問題的 hook 預設只給 30 秒 | 一個常數 |
| I7 | `init` 第一次改一個已存在的設定檔之前，先複製成 `<檔名>.before-contextbase`，之後不再覆蓋這份備份 | 讓使用者回得到安裝前的狀態 | — |
| I8 | `Agent Memory/` 裡 `type` 不是 decision、progress、fact 的筆記，當一般筆記索引 | 使用者可能在那裡放自己的說明筆記 | — |
| I9 | 除錯用的 `CONTEXTBASE_PROBE_LOG` 留在正式版：設了才記錄 MCP 的往來，另設 `CONTEXTBASE_PROBE_REDACT=1` 時不記工具參數的內容 | 之後排查 client 的行為還用得到 | 移除 |
| I10 | `recent` 工具在 vault 根目錄時最多列 10 個主題、輸出上限 6,000 字元；開工注入維持 1,500 字元 | `recent` 是 agent 主動要的，可以給多一點 | 常數 |
| I11 | 記憶的摘要最多 200 字元，檔名取摘要的前 40 字 | 檔名太長，在 Obsidian 裡不好讀 | 常數 |
